🧭 UI/UX 설계 명세서 (v2.3 - 최종 확정안)

1. UI/UX 핵심 철학
   "지도가 아닌, 비서 (Secretary, not the Map)": 앱의 기본 목적은 '경로 검색'이 아니라 '여정 케어'입니다. 사용자의 정신적 부담(Mental Load)을 최소화하는 것을 최우선으로 합니다.

"카드 우선, 지도 차선 (Card-First, Map-Second)": 사용자는 '요약된 결론(카드)'을 먼저 보고, '상세 근거(지도)'는 원할 때만(On-Demand) 확인합니다.

"맥락 인지 (Context-Aware)": 앱의 UI는 v3.0 로직에 따라 능동적으로 스스로 변화하며, '출퇴근 시간'과 '그 외 시간'을 구분합니다.

"신뢰도 높은 제안 (High-Trust)": 모든 제안(Logic 2.2)은 "왜" 이 제안을 하는지 명확한 근거(예: "✅ 환승 4분 여유", "혼잡도: 혼잡")를 함께 제시해야 합니다.

2. [핵심] Ambient Feedback (배경색 알림) 로직
   v3.0 시스템 로직에 따라 앱의 '전체 화면 배경색'이 사용자의 상태를 본능적으로 알립니다.

1. 🔵 파란색 (정상 / Default)

조건: 내 여정이 '정상' 상태일 때. (Phase 1, 2)

의미: "모든 것이 순조롭습니다."

2. 🟠 주황색 (주의 / Warning)

조건: Logic 3.1 발동. 즉, 경로상에 '지연'이나 '위험 요소'(사고, 정체)가 감지되었으나, 아직 '목표 도착 시간'을 넘기지는 않은 상태.

의미: "문제가 생겼지만, 아직 지각은 아닙니다. 주의하세요."

3. 🔴 빨간색 (위기 / Alert)

조건: Logic 3.2 발동. 즉, '실제 예상 도착 시간'이 '목표 도착 시간'보다 늦어지는 것이 확정된 상태.

의미: "경고! 이대로 가면 지각합니다! [택시]를 타세요."

3. 정보 구조 (IA) 및 앱 상태 (App States)
   구조: '확장형 단일 브리핑 (Single, Expandable Briefing)'

앱의 핵심 탭은 [브리핑] 하나이며, 이 안에서 '즐겨찾기 여정'과 '범용 검색'이 모두 처리됩니다.

앱 상태 (App States):

[A] 비서 모드 (Briefing Mode)

Trigger: 사용자가 설정한 '출퇴근 알림 시간' (예: 평일 07:30-09:00, 18:00-19:30) 내에 앱을 실행한 경우.

Default UI: 컴포넌트 1이 '기본 상태(Collapsed)'로, [출근] 또는 [귀가] 탭이 활성화된 '포커스 카드' UI가 기본입니다.

[B] 탐색 모드 (Explore Mode)

Trigger: 비서 모드의 Trigger 시간을 제외한 모든 시간.

Default UI: 컴포넌트 1이 '확장 상태(Expanded)'로, **'범용 검색창'**이 기본으로 열려 있어, 사용자가 자유롭게 경로를 검색할 수 있습니다.

4. 화면 설계: [브리핑] 탭 상세
   4.1. 컴포넌트 1: 여정 선택기 (Journey Selector)
   UI (2가지 상태):

[기본 상태 (Collapsed)]: (비서 모드 Default)

[출근], [귀가], [헬스장] 등 즐겨찾기 탭과 [확장 검색(+)] 버튼이 표시됩니다.

[확장 상태 (Expanded)]: (탐색 모드 Default)

[확장 검색(+)]을 누르거나 탐색 모드일 때, 이 영역이 확장되어 [출발지] / [목적지]를 입력하는 '범용 검색창'이 나타납니다.

4.2. 컴포넌트 2: 핵심 캐러셀 (Primary Carousel)
역할: 화면 상단에 위치하며, 좌우로 스와이프 가능한 카드 묶음입니다.

UI: Hero 상태 카드, 날씨 카드, 대안 경로 카드 등으로 구성됩니다.

[카드 2.1: Hero 상태 카드] (기본 포커스)

역할: '두뇌' 카드. 항상 캐러셀의 첫 번째 슬라이드입니다. v3.0 로직의 '얼굴'입니다.

UI (Phase 1: 출발 전):

헤드라인: "지금 출발하세요!"

핵심: "5분 뒤 123번 버스 도착"

요약: "총 예상 소요 시간 45분"

(First Mile 대응): "(다음 버스: 456번 10분 뒤)" - 사용자가 버스를 놓칠 경우를 대비한 2차 정보 제공.

UI (Phase 2: 이동 중) [v2.2 수정]

헤드라인 (최종 결과): "회사 도착 8:48 (2분 빠름)"

핵심 다음 행동 (Next Action):

(환승 시) "다음: B역에서 9호선 환승 (7분 뒤)"

(하차 시) "다음: C역 하차 (3분 뒤)"

UI (Phase 3: 돌발상황):

Logic 3.1 (지연): 헤드라인 "⚠️ 5분 지연! (A구간 정체)"

Logic 3.2 (위기): 헤드라인 "🚨 지각 확정! [택시 호출하기]"

'퇴근 모드' 셀렉터:

컴포넌트 1에서 [귀가] 탭이 선택되었을 때만, 이 카드 오른쪽 상단에 [ ⚡️ 빠르게 ] (기본값) / [ 🧘‍♀️ 편안하게 ] 셀렉터가 표시됩니다.

팝업 없이, 옵션 변경 시 하위 카드 내용 전체가 해당 기준으로 즉시 재계산(Refresh)됩니다.

Interaction: 탭(Tap) 시 → 상세 경로 지도 표시 (범용 검색 UI의 지도 기능 호출).

[카드 2.2: 날씨 카드]

UI: "현재 15°C, 비 예보 70%"

Interaction: 탭(Tap) 시 → 상세 날씨 페이지 (모달) 표시.

[카드 2.3: 대안 경로 카드] (조건부)

UI: "💡 7분 단축 경로 발견!" (Logic 2.2 발동 시)

상태: 평소에는 숨겨져(Hidden) 있습니다.

Interaction: 탭(Tap) 시 → '현재 경로'와 '제안 경로'를 비교하는 상세 경로 비교 (모달) 표시.

4.3. 컴포넌트 3: 단계별 경로 카드 (Step-by-Step Cards)
UI: 핵심 캐러셀 아래에 위치하는 수직 스크롤 영역.

디자인:

도보: 🚶 아이콘, 점선 (v3.0 'First/Last Mile' 반영)

교통수단: 🚌 🚇 아이콘, 해당 호선/버스 고유색 라인.

로직 표시:

Logic 2.3: "빠른 환승: 3-2칸 추천"

Logic 2.2: "혼잡도: 혼잡"

5. 핵심 상호작용: '능동적 포커싱'
   [정상/주의/위기] - 배경색 + Hero 카드

Logic 3.1 (지연 감지) → **배경색**이 <b>🟠</b>주황색으로 변하고 + 카드 2.1 (Hero)의 내용이 "⚠️ 5분 지연!"으로 업데이트됩니다.

Logic 3.2 (지각 확정) → **배경색**이 <b>🔴</b>빨간색으로 변하고 + 카드 2.1 (Hero)의 내용이 "🚨 지각 확정!"으로 업데이트됩니다.

[경로 제안] - 캐러셀 자동 슬라이드

Logic 2.2 (더 나은 경로)가 발동되면:

카드 2.3 (대안 경로)이 숨김(Hidden) → 표시(Visible) 상태로 변경됩니다.

핵심 캐러셀(C2)이 자동으로 카드 1에서 카드 2.3으로 슬라이드됩니다.

사용자는 "💡 7분 단축?"이라는 제안을 즉시 인지하게 됩니다.

6. 예외 상황 처리 (Exception Handling UI)
   데이터 수신 불가 (Offline State) UI

Trigger: GPS 또는 모바일 데이터(LTE/5G)가 일정 시간(예: 30초) 이상 수신되지 않을 때.

UI Change 1 (배너): 앱 최상단에 **'경고 배너'**가 표시됩니다.

(예) "⚠️ 실시간 정보 수신 불가. (마지막 업데이트: 1분 전)"

UI Change 2 (데이터 영역): 실시간 정보(예: "3분 뒤 도착", "예상 도착 8:48") 영역이 **회색(Grayscale)**으로 처리되거나 (업데이트 안 됨) 텍스트가 표시됩니다.

7. [확정] UI 연동을 위한 필요 데이터 명세
   이 UI를 완벽하게 구동하기 위해 백엔드(서버)와 프론트엔드(앱) 간에 다음과 같은 데이터 통신이 필요합니다.

7.1. 외부 API (실시간 데이터)
실시간 대중교통 정보 (API)

내용: 버스/지하철 실시간 위치, 노선도, 정류장/역별 도착 예정 시간.

연결 UI:

C2.1 (Hero 카드): "5분 뒤 123번 버스 도착", "다음: B역 하차 (3분 뒤)"

C3 (단계별 카드): 각 단계별 소요 시간.

실시간 도로 교통 상황 (TPEG 등 API)

내용: 경로상 도로 정체, 사고, 공사, 집회 정보.

연결 로직: Logic 3.1 (지연 감지)의 핵심 입력값.

경로 탐색 엔진 (API)

내용: 출발지-목적지 간 (대중교통, 도보) 전체 경로 계산.

연결 UI:

C1 (여정 선택기)의 '범용 검색' 시 사용.

C2.3 (대안 경로 카드): Logic 2.2가 대안 경로를 탐색할 때 사용.

실시간 혼잡도 (API)

내용: SKT/KT 등 통신사 기반 지하철/버스 칸별, 역별 혼잡도.

연결 UI: C3 (단계별 카드)의 "혼잡도: 혼잡" 표시.

날씨 (API)

내용: 현재 날씨 및 예보.

연결 UI: C2.2 (날씨 카드)

택시 호출 (API)

내용: 예상 소요 시간 및 요금, 앱 연동.

연결 로직: Logic 3.2 (지각 확정) → C2.1 (Hero 카드)의 [택시 호출하기] 버튼.

부가 정보 (API)

내용: 지하철 '빠른 환승' 위치 데이터.

연결 UI: C3 (단계별 카드)의 "빠른 환승: 3-2칸 추천"

7.2. 사용자 데이터 (앱 내부/서버 저장)
사용자 설정값 (DB)

내용: [집], [회사] 주소, [출근] 목표 도착 시각, [알림 시간]

연결 로직: IA (앱 상태)를 '비서 모드'로 전환하는 기준.

First/Last Mile 시간 (DB)

내용: '집→정류장' 도보 시간(5분), '역→회사' 도보 시간(7분).

연결 로직: Logic 1.1, 1.2가 '지금 출발' 시간을 정확히 계산하는 데 사용.

사용자 GPS (실시간/Device)

내용: 사용자의 현재 실시간 위치.

연결 로직: Logic 2.1(탑승 인지), Logic 3.1(내 위치 기반 지연 감지) 등 모든 v3.0 로직의 핵심.

7.3. [핵심] 내부 축적 데이터 (자체 백엔드 DB)
구간별/시간대별 평균 소요시간 (DB)

내용: (A정류장 → B정류장, 평일 8시) = '평균 7분'

연결 로직: Logic 3.1 (지연 감지)의 **'기준점'**이 되는 가장 중요한 데이터. (실시간 12분 - '평균 7분' = 5분 지연 감지)

필요 기술: 사용자들의 이동 데이터를 지속적으로 수집하고 정제하여 이 '평균' 데이터를 고도화하는 백엔드 로직.
