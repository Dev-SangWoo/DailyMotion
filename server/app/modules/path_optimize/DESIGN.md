🚀 개인 맞춤형 출퇴근 비서 시스템 설계 명세서 (v3.0)
1. 시스템 개요
시스템 목표: 사용자의 출퇴근 경험을 '수동적 정보 확인'에서 '능동적 실시간 케어'로 전환한다. 사용자가 묻기 전에 필요한 정보를 선제적으로 제공하며, 돌발 상황에 즉각 반응하여 사용자의 '지각'을 방지하고 '심리적/육체적 피로감'을 해소한다.

핵심 컨셉: "Just in Time, Just for Me" - 나의 습관과 오늘의 상황에 맞춰, 지금 꼭 필요한 정보만 알아서 챙겨준다.

2. 시스템 모드 (System Modes)
시스템은 사용자의 현재 여정이 '출근'인지 '퇴근'인지에 따라 두 가지 다른 모드로 작동합니다.

2.1. 📍 출근 모드 (Commute Mode)

핵심 목표: 목표 도착 시각 준수 (지각 방지)

작동 특징: '시간'과 '확실성'을 최우선으로, Logic 1.2(마지노선), Logic 3.2(택시 제안) 등이 자동으로 강하게 개입합니다.

2.2. 🏠 퇴근 모드 (Retreat Mode)

핵심 목표: 사용자의 '그날의 니즈' 충족 (속도 vs. 편안함)

작동 특징: 목표 도착 시각이 없는 대신, Logic 1.1에서 사용자의 **'퇴근 목표'**를 먼저 묻고, 그에 맞춘 대안(예: 착석 경로)을 제안합니다.

3. 필수 사용자 설정 (Prerequisites)
시스템이 '문 앞(Door-to-Door)' 기준으로 작동하기 위해 최초 1회 입력받는 정보입니다.

[필수] 출근지 (문 앞) (예: 집 주소)

[필수] 목적지 (문 앞) (예: 회사 주소)

[필수] 목표 도착 시각 (출근 모드 전용, 예: 오전 8시 50분)

[선택] 선호 경로 (1~3개): '최단 시간', '최소 환승', '착석 선호' 등 속성 지정

[선택] 알림 시작 시각: (예: 출근 07:30, 퇴근 18:00)

[신규/자동] 1차 탑승지 도보 시간 (First Mile): (예: '집' → 'A정류장' 5분) - 최초 입력 또는 자동 학습

[신규/자동] 최종 하차지 도보 시간 (Last Mile): (예: 'B역' → '회사' 7분) - 최초 입력 또는 자동 학습

4. 핵심 로직 흐름 (Phased Logic Flow)
Phase 1: 출발 전 (Pre-Departure)
Logic 1.1: 능동적 출발 알림

[출근 모드] (Trigger: 알림 시작 시각)

First Mile 도보 시간(5분)을 계산하여 푸시 알림.

(예시) "8:50 도착을 위해, 지금 집에서 출발하셔서 5분 뒤 오는 [123번 버스]를 타세요."

[퇴근 모드] (Trigger: 알림 시작 시각 또는 회사 근처 GPS 감지 시)

사용자에게 '오늘의 퇴근 목표'를 묻는 알림.

(예시) "퇴근 시간입니다. 오늘은 어떻게 가시겠어요? [A. 가장 빠르게] [B. 편안하게(착석)] [C. 평소 경로]"

Logic 1.2: 마지노선 경고

[출근 모드]

Logic 1.1을 놓쳤을 경우, 목표 도착 시각을 맞출 수 있는 마지막 교통수단 알림.

(예시) "⚠️지각 주의! 8:50 도착을 위한 마지막 버스[456번]가 8분 뒤 도착합니다. (도보 5분 포함, 지금 출발하셔야 합니다!)"

[퇴근 모드]

(비활성화 또는 '막차 알림'으로 대체) (예: "선택하신 [B. 편안한 경로]의 막차가 30분 뒤입니다.")

Phase 2: 이동 중 (On-Trip)
Logic 2.1: 자동 모드 전환 (Context Awareness)

(모드 공통) GPS 기반 '탑승' 상태 인지 시, '정류장 기준'에서 **'최종 목적지(문 앞) 도착 예정 시간'**으로 화면 자동 전환.

Logic 2.2: '고신뢰' 대안 경로 제안

(모드 공통) 비현실적 제안(지금 내려서 걷기)을 막기 위해 '다가오는 환승 지점'을 기준으로 탐색합니다.

(모드 공통) 제안은 다음 **3가지 엄격한 조건(Gate)**을 통과해야만 사용자에게 알림:

조건 1: 확실한 이득 (High Threshold)

[출근] 현저히(예: 7~10분 이상) 빨라야 함.

[퇴근] '편안함' 선택 시, '착석 가능성'이 확실히 높아야 함.

조건 2: 환승 확정성 (Transfer Certainty)

(수정됨) 제안한 경로로 환승 시, (현재 버스 도착 시간)과 (환승 버스 실시간 도착 시간)을 비교, 최소 환승 성공 시간(예: 3분)이 확보될 때만 제안. (즉, "내렸는데 버스 떠나는" 상황 방지)

조건 3: 경험의 질 (Quality of Experience)

'지하철/버스 혼잡도' 데이터를 반영하여 고지.

(예시) "더 빠른 경로 발견! (10분 단축) / 다음 'A역' [9호선 급행] 환승하세요. (단, 현재 혼잡도 '매우 높음')"

Logic 2.3: '탑승/환승' 최적화 가이드

(모드 공통) 현재 경로 이용 시, 이동 경험을 미세하게 최적화.

(예시 1) "다음 'B역' 환승을 위해, **'5-2번 칸'**에 탑승하세요."

(예시 2) "지금 들어오는 열차는 3번, 8번 칸이 가장 여유 있습니다."

Logic 2.4: 환승 리마인더 & 실시간 환승 열차 안내

(모드 공통) 사용자가 **기본 경로**를 따라 이동 중일 때, '다가오는 환승역' 근처에서 **환승해야 한다는 알림**과 함께 **환승 열차/버스의 실시간 도착 정보**를 제공한다.

- 대상 상황 예시:
  - 출발지: 남구로역, 도착지: 부천역
  - 경로: 남구로역 → (1호선) 온수역 → (7호선) 부천역
  - 사용자가 온수역 인근에 접근했을 때:
    - "다음 역에서 7호선으로 환승해야 합니다."
    - "부천 방면 7호선 열차가 3분 후 도착 예정입니다."

**핵심 목표**

- 사용자가 **환승 시점을 놓치지 않도록** 도와준다.
- 환승 결정을 할 때 **실시간 도착 정보**를 함께 제공해 불필요한 불안감을 줄인다.
- Logic 2.2(고신뢰 대안 경로)와는 별도로, **현재 선택된 기본 경로**에 대한 **'리마인더 성격'의 가이드**를 제공한다.

**Trigger 조건 (환승 리마인더 발동)**:

1. ODSay 경로 정보 기준:
   - 현재 경로의 `subPath` 중 `trafficType`이 지하철/버스인 구간에서
   - 다음 구간이 다른 노선/다른 교통수단으로 바뀌는 지점(=환승역)을 환승 후보로 정의
2. GPS 기준:
   - 사용자의 현재 위치가 환승역 좌표 기준 **반경 X m 이내** (예: 300~500m)
3. 시간 기준:
   - 환승역 도착 예상 시간 기준, **환승 열차/버스 출발까지 Y분 이상 남아 있을 때** (예: 2~3분 이상)

위 조건을 모두 만족하는 경우, 아래의 알림을 1회 발송한다.

**알림 내용 (예시 메시지)**

- 기본 형태:
  - "다음 역인 [온수역]에서 [7호선 부천 방면]으로 환승하셔야 합니다."
  - "부천 방면 열차가 약 [3분 후] 도착 예정입니다."
- 추가 정보(선택):
  - "현재 열차 혼잡도: 보통 / 다음 열차는 여유"
  - "환승 통로와 가까운 칸: 5-2번"

**실시간 데이터 연동**

- 실시간 지하철 API (예: 서울시 `realtimeStationArrival`) 또는 버스 실시간 API를 사용해 다음 정보를 조회:
  - 환승역(`statnNm`) + 환승 노선(`subwayId` / 노선 ID)
  - 상/하행(`updnLine`) 및 방면 정보
  - `barvlDt`(도착까지 남은 시간, 초 단위)
- 조회 결과를 분 단위로 변환하여 메시지에 포함:
  - 예: `barvlDt = 180` → "3분 후 도착"
- 실시간 조회 실패 시:
  - 통계 데이터(평균 도착 간격) 또는 ODSay 기준 시간으로 Fallback
  - 예: "실시간 정보를 불러올 수 없습니다. 평균적으로 4~6분 간격으로 운행됩니다."

**스마트 폴링(Logic 4.3)과의 연동**

- 환승역 반경 500m 이내에 진입하면:
  - `PollingFrequency.HIGH` (10초 단위)로 전환하여
  - 환승 구간에 한해 지하철/버스 실시간 도착 정보를 자주 업데이트
- 알림 발송 후에는:
  - 동일 환승에 대해 중복 알림이 발생하지 않도록, **해당 환승 지점에 대한 플래그**를 세션/상태에 저장
  - 필요 시, "다음 열차 기준으로 다시 환승 알림"을 보낼 수 있도록 정책 정의 (예: 사용자가 환승을 놓친 경우에만 재알림)

**성공 기준**

- 사용자가 환승역에 도착하기 전에:
  - "다음 역에서 무엇으로 갈아타야 하는지"와
  - "환승 열차/버스가 언제 도착하는지"
  를 명확히 인지할 수 있어야 한다.
- 불필요한 과다 알림을 방지:
  - 같은 환승 지점에 대해 짧은 시간 내에 **한 번만** 안내 (재탑승/재경로 상황 등 특별 케이스는 별도 정책).

Phase 3: 돌발상황 대응 (Exception Handling)
Logic 3.1: '예상-평균 지연차' 기반 돌발상황 감지

(모드 공통) (구간, 시간대)별 '평균 소요시간' DB (예: A→B 7분)와 '실시간 예상 소요시간'(예: 12분)을 비교.

지연차(5분)가 임계값 초과 시 '돌발상황'으로 인지하고 즉시 경고. (원인이 사고든 집회든 '결과'만 감지)

(예시) "⚠️지연 감지! [A정류장] 부근이 평소보다 5분 이상 늦어지고 있습니다."

Logic 3.2: 최종 대안 제시 (택시)

[출근 모드]

(Trigger) Logic 3.1 지연으로 인해 어떤 대중교통으로도 목표 도착 시각을 맞출 수 없을 때.

(예시) "🚨지각 확정! 대중교통 이용 시 도착 예상. 지금 [택시] 탑승 시 도착 가능합니다. [택시 호출하기]"

[퇴근 모드]

(Trigger) Logic 3.1 지연 등으로 인해 **'대중교통 막차'**가 끊겼을 때만 제안.

5. 필요 데이터 및 기술
사용자 데이터: GPS 위치 (실시간), 사용자 설정 (모드별 선호도, First/Last Mile 시간)

외부 데이터 (API):

실시간 대중교통 정보 (버스/지하철 위치, 도착 시간)

실시간 도로 교통 상황 (TPEG), 실시간 지하철/버스 혼잡도

경로 탐색 엔진, 택시 호출 API

지하철 '빠른 환승' 위치 데이터

[중요] 내부 축적 데이터:

구간별/시간대별 평균 소요시간 DB (Logic 3.1의 핵심)

핵심 기술:

Context Awareness: 사용자의 상태(대기, 도보, 탑승) 및 모드(출근/퇴근) 구분.

Predictive Engine: '실시간 예측 시간'과 '과거 평균 시간'을 비교하는 로직 (Logic 3.1).

[신규] 스마트 폴링 (Adaptive Update / Smart Polling)

목표: 배터리 및 데이터 소모 최적화.

로직: 사용자의 상태와 위치에 따라 GPS/API 호출 빈도를 동적으로 조절.

[High Frequency] : '환승 지점' 접근 시, '주요 정체 구간'(Logic 3.1) 진입 시, '출발/마지노선' 알림 직전.

[Low Frequency] : '순항 구간'(지하철 터널, 고속도로 등) 이동 시, '정지' 상태(회사/집)일 때.
